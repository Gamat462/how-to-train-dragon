Minggu 1–4
Minggu 1

Bertanya ke database: SELECT, WHERE, ORDER BY

Setelah minggu ini kamu bisa: mengambil persis baris yang kamu mau dari tabel, dalam urutan yang kamu mau.

Cara membaca query SQL: selalu dari FROM dulu (tabel mana), lalu WHERE (baris mana), lalu SELECT (kolom mana), lalu ORDER BY (urutannya). Kamu menulis SELECT di atas, tapi database menjalankan FROM dulu.

SELECT … FROM — ambil kolom

Bintang (*) artinya semua kolom. Di kantor, sebutkan kolomnya — lebih cepat dan lebih jelas.

SELECT * FROM penjualan;                    -- semua kolom, semua baris
SELECT tanggal, produk, total FROM penjualan;   -- tiga kolom saja

WHERE — saring baris

Ini padanan filter. Teks pakai kutip satu, angka tidak.

SELECT * FROM penjualan WHERE kota = 'Bandung';
SELECT * FROM penjualan WHERE jumlah >= 15;
SELECT * FROM penjualan WHERE kota = 'Jakarta' AND kategori = 'Makanan';
SELECT * FROM penjualan WHERE produk = 'Kopi Susu' OR produk = 'Americano';
SELECT * FROM penjualan WHERE produk IN ('Kopi Susu', 'Americano');   -- sama, lebih rapi
SELECT * FROM penjualan WHERE tanggal BETWEEN '2026-02-01' AND '2026-02-28';
SELECT * FROM penjualan WHERE produk LIKE 'Kopi%';   -- diawali "Kopi"

Baris ke-3 menghasilkan 7 baris: semua Roti Bakar dan Croissant yang dijual di Jakarta.

ORDER BY · LIMIT — urutkan, ambil sebagian

DESC = dari besar ke kecil. Tanpa DESC = kecil ke besar.

SELECT tanggal, produk, kota, total
FROM penjualan
ORDER BY total DESC
LIMIT 3;
tanggal     produk     kota     total
2026-03-18  Kopi Susu  Bandung  550000
2026-03-01  Kopi Susu  Jakarta  484000
2026-02-16  Kopi Susu  Bandung  440000

DISTINCT — nilai unik

SELECT DISTINCT produk FROM penjualan;     -- 4 baris
SELECT DISTINCT kota, kategori FROM penjualan;   -- kombinasi unik: 4 baris

Tiga kebiasaan sejak hari pertama

  • Akhiri dengan titik koma ;. Di beberapa alat wajib, di semua alat aman.
  • Huruf besar untuk kata kunci (SELECT, FROM), huruf kecil untuk nama tabel/kolom. Bukan aturan, tapi konvensi yang membuat query terbaca.
  • Satu klausa per baris untuk query yang lebih dari satu baris. Lihat contoh ORDER BY di atas.
LATIHAN SQL MINGGU 1

Lima query

  1. Semua transaksi di Bandung, urut dari tanggal paling lama. Berapa baris?
  2. Tiga transaksi dengan jumlah porsi terbanyak (bukan total rupiah).
  3. Transaksi bulan Maret yang porsinya 10 atau lebih. Tampilkan tanggal, produk, jumlah.
  4. Semua transaksi Makanan di Jakarta. Berapa baris?
  5. Transaksi yang total-nya antara 150.000 dan 250.000, urut dari total terbesar.
Kunci jawaban 
  1. SELECT * FROM penjualan WHERE kota = 'Bandung' ORDER BY tanggal;
    11 baris.
  2. SELECT tanggal, produk, jumlah FROM penjualan ORDER BY jumlah DESC LIMIT 3;
    25 (Kopi Susu, 18 Mar), 22 (Kopi Susu, 1 Mar), 20 (Kopi Susu, 16 Feb).
  3. SELECT tanggal, produk, jumlah FROM penjualan
WHERE tanggal >= '2026-03-01' AND jumlah >= 10;
    4 baris: Kopi Susu 22, Roti Bakar 13, Kopi Susu 25, Americano 11.
  4. SELECT * FROM penjualan WHERE kategori = 'Makanan' AND kota = 'Jakarta';
    7 baris.
  5. SELECT * FROM penjualan WHERE total BETWEEN 150000 AND 250000 ORDER BY total DESC;
    8 baris: 216.000, 198.000, 195.000, 180.000 (Americano, Jan), 180.000 (Croissant, Mar), 165.000, 162.000, 160.000. Kebiasaan baik: setelah menyaring, selalu cek jumlah barisnya dengan SELECT COUNT(*) … WHERE … — mudah sekali salah hitung kalau hanya melihat dengan mata.
Minggu 2

Meringkas: COUNT, SUM, GROUP BY, HAVING

Setelah minggu ini kamu bisa: menjawab "berapa total X per Y" — pertanyaan yang muncul di 90% pekerjaan analis dan di hampir semua wawancara.

Fungsi agregat — satu angka dari banyak baris

SELECT
  COUNT(*)      AS jumlah_transaksi,
  SUM(total)    AS omzet,
  AVG(total)    AS rata_rata,
  MIN(total)    AS terkecil,
  MAX(total)    AS terbesar
FROM penjualan;
jumlah_transaksi  omzet    rata_rata   terkecil  terbesar
24                5050000  210416.67   75000     550000

AS memberi nama kolom hasil. Selalu pakai — hasil tanpa nama tidak bisa dibaca orang lain.

GROUP BY — satu angka per kelompok

Ini inti minggu ini. "Omzet per produk" = kelompokkan berdasarkan produk, lalu jumlahkan tiap kelompok.

SELECT produk, SUM(total) AS omzet, SUM(jumlah) AS porsi
FROM penjualan
GROUP BY produk
ORDER BY omzet DESC;
produk      omzet    porsi
Kopi Susu   2464000  112
Americano   1026000  57
Roti Bakar  780000   52
Croissant   780000   39
Aturan emas GROUP BY: setiap kolom di SELECT harus ada di GROUP BY atau dibungkus fungsi agregat. SELECT produk, kota, SUM(total) … GROUP BY produk akan error (atau memberi hasil ngawur) karena kota tidak dikelompokkan dan tidak diagregat.

GROUP BY dua kolom

SELECT kota, kategori, SUM(jumlah) AS porsi
FROM penjualan
GROUP BY kota, kategori
ORDER BY kota, kategori;
kota     kategori  porsi
Bandung  Makanan   39
Bandung  Minuman   84
Jakarta  Makanan   52
Jakarta  Minuman   85

Mengelompokkan per bulan

Tanggal harus dipotong jadi "2026-01" dulu. Di SQLite pakai substr; di PostgreSQL pakai to_char(tanggal, 'YYYY-MM').

SELECT substr(tanggal, 1, 7) AS bulan, SUM(total) AS omzet, COUNT(*) AS transaksi
FROM penjualan
GROUP BY bulan
ORDER BY bulan;
bulan    omzet    transaksi
2026-01  1328000  8
2026-02  1693000  8
2026-03  2029000  8

HAVING — saring setelah dikelompokkan

WHERE menyaring baris sebelum dikelompokkan. HAVING menyaring kelompok setelah dihitung. "Produk yang porsinya lebih dari 50" adalah syarat pada hasil SUM — jadi HAVING.

SELECT produk, SUM(jumlah) AS porsi
FROM penjualan
GROUP BY produk
HAVING SUM(jumlah) > 50;
produk      porsi
Kopi Susu   112
Americano   57
Roti Bakar  52

Urutan eksekusi yang harus kamu hafal

FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT. Ini menjelaskan kenapa kamu tidak bisa pakai alias dari SELECT di dalam WHERE (WHERE jalan duluan), dan kenapa HAVING bisa memakai SUM (GROUP BY sudah jalan).

LATIHAN SQL MINGGU 2

Enam query

  1. Jumlah transaksi dan rata-rata total per kota. Kota mana yang rata-rata transaksinya lebih besar?
  2. Omzet per kategori, plus persentasenya dari total keseluruhan (petunjuk: SUM(total) * 100.0 / 5050000; nanti di minggu 4 kita buat tanpa angka hardcode).
  3. Porsi terjual per produk per bulan. Produk mana yang naik terus tiap bulan?
  4. Kota yang jumlah transaksinya lebih dari 12.
  5. Rata-rata porsi per transaksi untuk tiap produk, urut dari terbesar.
  6. Bulan dengan omzet Bandung di atas 800.000.
Kunci jawaban 
  1. SELECT kota, COUNT(*) AS transaksi, AVG(total) AS rata_rata
FROM penjualan GROUP BY kota;
    Jakarta 13 transaksi, rata-rata 201.000. Bandung 11 transaksi, rata-rata 221.545. Bandung lebih besar per transaksi meski total omzetnya lebih kecil.
  2. SELECT kategori, SUM(total) AS omzet, SUM(total) * 100.0 / 5050000 AS persen
FROM penjualan GROUP BY kategori;
    Minuman 3.490.000 (69,1%), Makanan 1.560.000 (30,9%). Perhatikan 100.0 bukan 100 — tanpa desimal, SQLite membulatkan ke bilangan bulat.
  3. SELECT substr(tanggal,1,7) AS bulan, produk, SUM(jumlah) AS porsi
FROM penjualan GROUP BY bulan, produk ORDER BY produk, bulan;
    Kopi Susu: 27 → 38 → 47. Americano: 18 → 19 → 20. Roti Bakar: 14 → 17 → 21. Croissant: 10 → 13 → 16. Semua naik — Kopi Susu paling cepat.
  4. SELECT kota, COUNT(*) AS transaksi FROM penjualan
GROUP BY kota HAVING COUNT(*) > 12;
    Hanya Jakarta (13).
  5. SELECT produk, AVG(jumlah) AS rata_porsi FROM penjualan
GROUP BY produk ORDER BY rata_porsi DESC;
    Kopi Susu 18,67 · Americano 9,5 · Roti Bakar 8,67 · Croissant 6,5.
  6. SELECT substr(tanggal,1,7) AS bulan, SUM(total) AS omzet
FROM penjualan WHERE kota = 'Bandung'
GROUP BY bulan HAVING SUM(total) > 800000;
    Februari 831.000 dan Maret 1.012.000. (Januari 594.000 tidak lolos.) Perhatikan: syarat kota di WHERE, syarat omzet di HAVING.
Minggu 3

Menggabungkan tabel: JOIN

Setelah minggu ini kamu bisa: menjawab pertanyaan yang jawabannya tersebar di dua tabel — misalnya "berapa laba?", yang butuh tabel penjualan dan tabel produk.

Kenapa data dipecah jadi banyak tabel? Kalau harga Kopi Susu ditulis di tiap baris penjualan, saat harganya naik kamu harus mengubah 6 baris (di dunia nyata: jutaan). Dengan tabel produk terpisah, cukup ubah 1 baris. JOIN adalah cara "menyatukan kembali" saat kamu butuh keduanya.

Tabel produk punya harga dan biaya_modal. Tabel penjualan punya jumlah. Laba per transaksi = jumlah × (harga − biaya_modal). Tidak ada satu tabel pun yang punya semuanya.

INNER JOIN — baris yang cocok di kedua tabel

SELECT
  p.tanggal,
  p.produk,
  p.jumlah,
  pr.harga,
  pr.biaya_modal,
  p.jumlah * (pr.harga - pr.biaya_modal) AS laba
FROM penjualan AS p
JOIN produk AS pr ON p.produk = pr.produk
ORDER BY laba DESC
LIMIT 3;
tanggal     produk     jumlah  harga  biaya_modal  laba
2026-03-18  Kopi Susu  25      22000  9000         325000
2026-03-01  Kopi Susu  22      22000  9000         286000
2026-02-16  Kopi Susu  20      22000  9000         260000

p dan pr adalah alias tabel — singkatan supaya tidak menulis nama panjang berulang. ON menyebut kolom apa yang "menjodohkan" kedua tabel. JOIN tanpa kata lain = INNER JOIN.

JOIN + GROUP BY — laba per produk

SELECT
  pr.produk,
  SUM(p.total) AS omzet,
  SUM(p.jumlah * (pr.harga - pr.biaya_modal)) AS laba
FROM penjualan p
JOIN produk pr ON p.produk = pr.produk
GROUP BY pr.produk
ORDER BY laba DESC;
produk      omzet    laba
Kopi Susu   2464000  1456000
Americano   1026000  684000
Roti Bakar  780000   416000
Croissant   780000   351000
Temuan yang tidak mungkin didapat dari satu tabel: Roti Bakar dan Croissant omzetnya sama persis, tapi Roti Bakar labanya lebih besar (416 vs 351 ribu). Croissant modalnya mahal. Ini jenis insight yang membuat pemilik kedai mendengarkan.

LEFT JOIN — semua baris kiri, cocok atau tidak

Tabel produk punya Matcha Latte yang belum pernah terjual. INNER JOIN akan menghilangkannya. LEFT JOIN mempertahankannya, dengan nilai kosong (NULL) di sisi kanan.

SELECT pr.produk, COUNT(p.id) AS transaksi, COALESCE(SUM(p.total), 0) AS omzet
FROM produk pr
LEFT JOIN penjualan p ON pr.produk = p.produk
GROUP BY pr.produk
ORDER BY omzet DESC;
produk        transaksi  omzet
Kopi Susu     6          2464000
Americano     6          1026000
Roti Bakar    6          780000
Croissant     6          780000
Matcha Latte  0          0

COALESCE(x, 0) = "kalau x kosong, pakai 0". Tanpa itu, omzet Matcha Latte tampil NULL. COUNT(p.id) bukan COUNT(*) — karena COUNT(*) akan menghitung baris NULL sebagai 1.

Anti-join — yang tidak punya pasangan

"Produk mana yang belum pernah terjual?" "Cabang mana yang belum ada transaksi?" Pola: LEFT JOIN lalu saring yang sisi kanannya NULL.

SELECT c.kota, c.manajer, c.tanggal_buka
FROM cabang c
LEFT JOIN penjualan p ON c.kota = p.kota
WHERE p.id IS NULL;
kota      manajer  tanggal_buka
Surabaya  Ayu      2026-04-01

Jebakan JOIN yang menjatuhkan banyak orang di wawancara

  • Baris berlipat ganda. Kalau tabel kanan punya 2 baris yang cocok untuk 1 baris kiri, hasilnya 2 baris. Total omzet tiba-tiba dua kali lipat. Selalu cek COUNT(*) sebelum dan sesudah JOIN.
  • INNER JOIN diam-diam membuang data. Kalau ada penjualan dengan nama produk yang salah ketik ("Kopi susu" huruf kecil), INNER JOIN ke produk akan menghilangkannya tanpa peringatan.
  • Syarat di WHERE vs ON pada LEFT JOIN. LEFT JOIN … WHERE p.kota = 'Jakarta' mengubah LEFT JOIN jadi INNER JOIN secara efektif, karena baris NULL tidak lolos WHERE. Kalau mau tetap LEFT, taruh syaratnya di ON.
LATIHAN SQL MINGGU 3

Lima query

  1. Laba per kota. Kota mana yang lebih menguntungkan?
  2. Margin (%) tiap produk: laba ÷ omzet × 100. Produk mana yang marginnya paling rendah?
  3. Semua produk beserta jumlah porsi terjual — termasuk yang 0.
  4. Gabungkan tiga tabel: tampilkan tanggal, produk, kota, nama manajer, dan laba, untuk 5 transaksi dengan laba tertinggi.
  5. Laba per bulan per kategori.
Kunci jawaban 
  1. SELECT p.kota, SUM(p.jumlah * (pr.harga - pr.biaya_modal)) AS laba
FROM penjualan p JOIN produk pr ON p.produk = pr.produk
GROUP BY p.kota;
    Jakarta 1.507.000 · Bandung 1.400.000. Total 2.907.000.
  2. SELECT pr.produk,
  SUM(p.jumlah * (pr.harga - pr.biaya_modal)) * 100.0 / SUM(p.total) AS margin
FROM penjualan p JOIN produk pr ON p.produk = pr.produk
GROUP BY pr.produk ORDER BY margin;
    Croissant 45% · Roti Bakar 53,3% · Kopi Susu 59,1% · Americano 66,7%. Croissant paling rendah.
  3. SELECT pr.produk, COALESCE(SUM(p.jumlah), 0) AS porsi
FROM produk pr LEFT JOIN penjualan p ON pr.produk = p.produk
GROUP BY pr.produk ORDER BY porsi DESC;
    112, 57, 52, 39, dan Matcha Latte 0.
  4. SELECT p.tanggal, p.produk, p.kota, c.manajer,
  p.jumlah * (pr.harga - pr.biaya_modal) AS laba
FROM penjualan p
JOIN produk pr ON p.produk = pr.produk
JOIN cabang c ON p.kota = c.kota
ORDER BY laba DESC LIMIT 5;
    Lima teratas semuanya Kopi Susu: 325.000 (Dimas), 286.000 (Rina), 260.000 (Dimas), 234.000 (Rina), 195.000 (Dimas).
  5. SELECT substr(p.tanggal,1,7) AS bulan, pr.kategori,
  SUM(p.jumlah * (pr.harga - pr.biaya_modal)) AS laba
FROM penjualan p JOIN produk pr ON p.produk = pr.produk
GROUP BY bulan, pr.kategori ORDER BY bulan, pr.kategori;
    Jan: Makanan 202.000, Minuman 567.000 · Feb: Makanan 253.000, Minuman 722.000 · Mar: Makanan 312.000, Minuman 851.000. (Jumlah semuanya 2.907.000 — selalu cek totalnya cocok dengan laba keseluruhan.)
Minggu 4 · Proyek

Window function & CTE — dan proyek SQL pertama

Setelah minggu ini kamu bisa: membandingkan baris dengan baris lain (bulan ini vs bulan lalu, peringkat, total berjalan) — materi yang membedakan "bisa SQL" dari "bisa SQL untuk kerja".

Bedanya dengan GROUP BY: GROUP BY meringkas banyak baris jadi satu. Window function menambah kolom ke tiap baris, dengan nilai yang dihitung dari "jendela" baris di sekitarnya. Jumlah baris tidak berubah.

RANK / ROW_NUMBER — peringkat

SELECT
  produk,
  SUM(total) AS omzet,
  RANK() OVER (ORDER BY SUM(total) DESC) AS peringkat
FROM penjualan
GROUP BY produk;
produk      omzet    peringkat
Kopi Susu   2464000  1
Americano   1026000  2
Roti Bakar  780000   3
Croissant   780000   3

RANK memberi angka sama untuk nilai seri (dan melompat: berikutnya 5). ROW_NUMBER selalu 1, 2, 3, 4 walau seri. DENSE_RANK seri tapi tidak melompat (1, 2, 3, 3, 4).

PARTITION BY — peringkat dalam tiap kelompok

"Transaksi terbesar di tiap kota" — peringkat dihitung ulang per kota.

SELECT tanggal, kota, produk, total,
  ROW_NUMBER() OVER (PARTITION BY kota ORDER BY total DESC) AS urutan
FROM penjualan;

Baris dengan urutan = 1: Bandung 550.000 (18 Mar) dan Jakarta 484.000 (1 Mar). Untuk mengambil hanya baris itu, kamu butuh CTE di bawah — karena WHERE tidak bisa memakai hasil window function langsung.

SUM() OVER — total berjalan

SELECT tanggal, produk, total,
  SUM(total) OVER (ORDER BY tanggal, id) AS omzet_kumulatif
FROM penjualan;
tanggal     produk      total   omzet_kumulatif
2026-01-03  Kopi Susu   264000  264000
2026-01-03  Roti Bakar  75000   339000
2026-01-05  Americano   144000  483000
...
2026-03-30  Croissant   180000  5050000

LAG — bandingkan dengan baris sebelumnya

Pertumbuhan bulan ke bulan. Ini query yang hampir pasti ditanya di wawancara.

WITH bulanan AS (
  SELECT substr(tanggal,1,7) AS bulan, SUM(total) AS omzet
  FROM penjualan
  GROUP BY bulan
)
SELECT
  bulan,
  omzet,
  LAG(omzet) OVER (ORDER BY bulan) AS omzet_bulan_lalu,
  (omzet - LAG(omzet) OVER (ORDER BY bulan)) * 100.0
     / LAG(omzet) OVER (ORDER BY bulan) AS pertumbuhan_persen
FROM bulanan;
bulan    omzet    omzet_bulan_lalu  pertumbuhan_persen
2026-01  1328000  NULL              NULL
2026-02  1693000  1328000           27.48
2026-03  2029000  1693000           19.85

Bagian WITH bulanan AS (…) adalah CTE: tabel sementara yang kamu beri nama, lalu dipakai di query utama. Ini cara memecah query panjang jadi langkah yang bisa dibaca. Kamu akan memakainya setiap hari.

CTE untuk persentase tanpa angka hardcode

WITH total_semua AS (
  SELECT SUM(total) AS grand FROM penjualan
)
SELECT p.kategori,
  SUM(p.total) AS omzet,
  SUM(p.total) * 100.0 / t.grand AS persen
FROM penjualan p, total_semua t
GROUP BY p.kategori, t.grand;

Minuman 69,1% · Makanan 30,9%. Sama seperti minggu 2, tapi kalau datanya bertambah, angkanya ikut benar sendiri.

LATIHAN SQL MINGGU 4

Empat query

  1. Pakai CTE + ROW_NUMBER untuk mengambil hanya transaksi terbesar di tiap kota (2 baris).
  2. Pertumbuhan porsi Kopi Susu bulan ke bulan, dalam persen.
  3. Untuk tiap transaksi, tampilkan total dan rata-rata total di kota yang sama (petunjuk: AVG(total) OVER (PARTITION BY kota)). Lalu tambahkan kolom selisihnya.
  4. Peringkat produk berdasarkan laba (butuh JOIN + window).
Kunci jawaban 
  1. WITH ranked AS (
  SELECT tanggal, kota, produk, total,
    ROW_NUMBER() OVER (PARTITION BY kota ORDER BY total DESC) AS rn
  FROM penjualan
)
SELECT tanggal, kota, produk, total FROM ranked WHERE rn = 1;
    Bandung 550.000 dan Jakarta 484.000.
  2. WITH ks AS (
  SELECT substr(tanggal,1,7) AS bulan, SUM(jumlah) AS porsi
  FROM penjualan WHERE produk = 'Kopi Susu' GROUP BY bulan
)
SELECT bulan, porsi,
  (porsi - LAG(porsi) OVER (ORDER BY bulan)) * 100.0 / LAG(porsi) OVER (ORDER BY bulan) AS tumbuh
FROM ks;
    27 → 38 (+40,7%) → 47 (+23,7%).
  3. SELECT tanggal, kota, total,
  AVG(total) OVER (PARTITION BY kota) AS rata_kota,
  total - AVG(total) OVER (PARTITION BY kota) AS selisih
FROM penjualan ORDER BY kota, selisih DESC;
    Rata-rata Jakarta 201.000, Bandung 221.545. Transaksi 550.000 di Bandung berada 328.455 di atas rata-rata kotanya.
  4. SELECT pr.produk,
  SUM(p.jumlah * (pr.harga - pr.biaya_modal)) AS laba,
  RANK() OVER (ORDER BY SUM(p.jumlah * (pr.harga - pr.biaya_modal)) DESC) AS peringkat
FROM penjualan p JOIN produk pr ON p.produk = pr.produk
GROUP BY pr.produk;
    Kopi Susu 1, Americano 2, Roti Bakar 3, Croissant 4 — tidak seri lagi, beda dengan peringkat omzet.

Langkah pembersihan standar

bersih = kotor.copy()

# 1. Teks: buang spasi, seragamkan huruf
for kol in ["produk", "kategori", "kota"]:
    bersih[kol] = bersih[kol].str.strip().str.title()

# 2. Tanggal: paksa jadi datetime, dua format sekaligus
bersih["tanggal"] = pd.to_datetime(bersih["tanggal"], format="mixed", dayfirst=True)

# 3. Duplikat
print("duplikat:", bersih.duplicated().sum())    # 1
bersih = bersih.drop_duplicates()

# 4. Nilai kosong: lihat dulu, baru putuskan
print(bersih.isna().sum())

# total kosong → bisa dihitung ulang dari jumlah × harga (butuh merge)
bersih = bersih.merge(produk[["produk","harga"]], on="produk", how="left")
bersih["total"] = bersih["total"].fillna(bersih["jumlah"] * bersih["harga"])

# jumlah kosong → bisa dihitung balik: total ÷ harga
bersih["jumlah"] = bersih["jumlah"].fillna(bersih["total"] / bersih["harga"])

# 5. Tipe data
bersih["jumlah"] = bersih["jumlah"].astype(int)
bersih["total"]  = bersih["total"].astype(int)

bersih
