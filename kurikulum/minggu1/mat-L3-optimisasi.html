Buktikan aturannya, jangan hafalkan

Untuk f(x) = x² − 4x + 7 dengan minimum x* = 2, satu langkah gradient descent adalah:

x_baru = x - lr*(2x - 4)
       = x - 2·lr·x + 4·lr
       = x(1 - 2·lr) + 4·lr

Kurangi 2 dari kedua ruas:

x_baru - 2 = x(1 - 2·lr) + 4·lr - 2
           = (1 - 2·lr)(x - 2)

Jadi: JARAK KE JAWABAN dikalikan (1 - 2·lr) setiap langkah.
|1 − 2·lr| Artinya Terjadi ketika
< 1jarak mengecil → sampai0 < lr < 1
= 0jarak jadi nol seketikalr = 0,5 (untuk fungsi ini)
= 1jarak tetap → berputar selamanyalr = 1
> 1jarak membesar → meledaklr > 1

Definisi konveks, dan cara memeriksanya

Fungsi konveks itu fungsi yang “berbentuk mangkuk”: tarik garis antara dua titik mana pun di grafiknya, garis itu tidak akan pernah jatuh di bawah grafik.

import numpy as np
def uji_konveks(f, a, b, n=2000, seed=0):
    rng = np.random.default_rng(seed)
    x1, x2 = rng.uniform(a, b, n), rng.uniform(a, b, n)
    t = rng.uniform(0, 1, n)
    kiri  = f(t*x1 + (1-t)*x2)          # nilai fungsi di titik tengah
    kanan = t*f(x1) + (1-t)*f(x2)       # nilai garis di titik tengah
    return (kiri <= kanan + 1e-9).mean()

f = lambda x: x**2 - 4*x + 7
g = lambda x: x**4 - 8*x**3 + 18*x**2 - 11*x
print("f konveks di", round(uji_konveks(f, -5, 5)*100, 2), "% pasangan titik")
print("g konveks di", round(uji_konveks(g, -1, 5)*100, 2), "% pasangan titik")
HARUS MUNCUL 
f konveks di 100.0 % pasangan titik
g konveks di 59.85 % pasangan titik
INI PEMBEDAANNYA Konveks itu sifat “semua atau tidak sama sekali”. f lolos 100% — ia konveks, dan gradient descent dijamin menemukan jawaban terbaik dari titik awal mana pun. g gagal di 40% pasangan titik, jadi ia tidak konveks, dan tidak ada jaminan apa pun.

HARI 4

Adu: gradient descent lawan rumus tertutup

± 3 jam
Tujuan hari ini: membuktikan bahwa gradient descent mendarat di tempat yang sama persis dengan rumus regresi di MAT L2 — lalu menjawab pertanyaan yang kutinggalkan menggantung: kenapa repot-repot mengulang kalau ada rumus?
1

Latih regresi dengan gradient descent

import numpy as np
np.random.seed(3)
n  = 500
x1 = np.random.uniform(0, 40, n); x2 = np.random.uniform(0, 10, n)
y  = 150_000 + 8_500*x1 + 22_000*x2 + np.random.normal(0, 25_000, n)
X  = np.column_stack([np.ones(n), x1, x2])

beta_tutup = np.linalg.lstsq(X, y, rcond=None)[0]     # cara MAT L2

# --- gradient descent, dengan pembakuan (alasannya di langkah 3) ---
mu, sd = X[:, 1:].mean(0), X[:, 1:].std(0)
Xs = X.copy(); Xs[:, 1:] = (X[:, 1:] - mu) / sd
ys_mu, ys_sd = y.mean(), y.std(); ys = (y - ys_mu) / ys_sd

b = np.zeros(3); mse = []
for i in range(3000):
    grad = (2/n) * Xs.T @ (Xs @ b - ys)
    b -= 0.1 * grad
    mse.append(np.mean((Xs @ b - ys)**2))

b_asli = np.empty(3)
b_asli[1:] = b[1:] * ys_sd / sd
b_asli[0]  = ys_mu + b[0]*ys_sd - (b_asli[1:] * mu).sum()

print("rumus tertutup   :", beta_tutup)
print("gradient descent :", b_asli)
print("selisih relatif  :", np.abs((b_asli - beta_tutup)/beta_tutup).max())

Jawaban atas pertanyaan yang menggantung dari MAT L2

Kalau rumus tertutup memberi jawaban langsung, kenapa seluruh machine learning modern memakai gradient descent? Saya mengukurnya — dan hasilnya membantah jawaban yang biasa diberikan orang.

import numpy as np, time
np.random.seed(3)
for p in (10, 100, 1000, 3000):
    n = 5000
    X = np.random.normal(0, 1, (n, p)); y = np.random.normal(0, 1, n)
    t0 = time.perf_counter(); np.linalg.inv(X.T @ X) @ X.T @ y
    t_inv = (time.perf_counter() - t0) * 1000
    t0 = time.perf_counter()
    b = np.zeros(p)
    for _ in range(200):
        b -= 0.001 * (2/n) * X.T @ (X @ b - y)
    t_gd = (time.perf_counter() - t0) * 1000
    print(f"p={p:>5}  inv: {t_inv:>9.2f} ms   GD 200 iterasi: {t_gd:>9.2f} ms")

Rumus tertutup menang di setiap ukuran yang bisa saya ukur — bahkan pada 3.000 fitur. Kalau kamu pernah membaca bahwa “gradient descent dipakai karena lebih cepat pada data besar”, tabel ini membantahnya untuk regresi linear biasa. Saya menuliskannya apa adanya, termasuk ketika hasilnya tidak cocok dengan cerita yang enak didengar.

Jadi kenapa gradient descent menguasai machine learning modern? Tiga alasan yang sebenarnya, dan tidak satu pun soal kecepatan pada kasus di atas:

Alasan sebenarnya Penjelasan
1. Kebanyakan model tidak PUNYA rumus tertutupRegresi logistik, SVM, dan setiap jaringan saraf tidak memiliki penyelesaian tertutup sama sekali. Di situ gradient descent bukan alternatif yang lebih lambat — ia satu-satunya jalan. Ini alasan terpenting.
2. Memori, bukan waktuRumus tertutup butuh seluruh X di memori sekaligus dan membentuk matriks p×p. Pada p = 100.000, matriks itu 10 miliar sel — tidak muat, berapa pun waktu yang kamu punya. Gradient descent bisa jalan satu potongan pada satu waktu, persis chunksize di Python Produksi.
3. Perbandingan di atas tidak adil sejak awalSaya memberi gradient descent 200 iterasi tanpa memeriksa apakah ia sudah cukup. Dengan early stopping dan learning rate yang disetel, ia jauh lebih cepat. Tapi menyetelnya butuh percobaan — dan itu sendiri biaya.
JAWABANNYA Kesimpulan praktis: untuk regresi linear di data yang muat di memori, pakai np.linalg.lstsq. Ia lebih cepat, lebih tepat, dan tidak ada yang perlu disetel. Gradient descent kamu pelajari bukan untuk menggantikannya, tapi karena ia satu-satunya alat untuk model yang akan kamu temui di MAT L4.

HARI 5

Penskalaan fitur: mengubah lembah lonjong jadi mangkuk bundar

± 2,5 jam
Tujuan hari ini: mengukur sendiri berapa besar pengaruh pembakuan fitur, dan bisa menjelaskan kenapa dengan satu angka: condition number.
1

Ukur bentuk lembahnya

Bentuk permukaan yang didaki gradient descent ditentukan matriks Hessian. Eigenvalue-nya memberi tahu seberapa curam ke tiap arah.

import numpy as np
np.random.seed(3)
n  = 500
x1 = np.random.uniform(0, 40, n); x2 = np.random.uniform(0, 10, n)
X  = np.column_stack([np.ones(n), x1, x2])
Xs = X.copy(); Xs[:, 1:] = (X[:, 1:] - X[:, 1:].mean(0)) / X[:, 1:].std(0)

for label, M in (("TANPA dibakukan ", X), ("DENGAN dibakukan", Xs)):
    H = (2/n) * M.T @ M
    ev = np.linalg.eigvalsh(H)
    print(f"{label}  min {ev.min():.4e}  max {ev.max():.4e}"
          f"  condition number {ev.max()/ev.min():.4e}")

CARA MEMBACANYA

Condition number turun dari 4.022 menjadi 1,02 — hampir 4.000 kali.

Bacanya begini: condition number adalah seberapa lonjong lembahnya. Nilai 1 berarti mangkuk bundar sempurna — gradient descent meluncur lurus ke dasar. Nilai 4.022 berarti ngarai sempit dan panjang: gradiennya menunjuk ke dinding, bukan ke dasar, jadi ia memantul zig-zag.

2

Buktikan pada waktu pelatihan sungguhan

import numpy as np
np.random.seed(3)
n  = 500
x1 = np.random.uniform(0, 40, n); x2 = np.random.uniform(0, 10, n)
y  = 150_000 + 8_500*x1 + 22_000*x2 + np.random.normal(0, 25_000, n)
X  = np.column_stack([np.ones(n), x1, x2])
ys = (y - y.mean()) / y.std()

def latih(M, lr, iterasi=3000):
    b = np.zeros(M.shape[1])
    for _ in range(iterasi):
        b -= lr * (2/len(M)) * M.T @ (M @ b - ys)
        if not np.isfinite(b).all():
            return None
    return np.mean((M @ b - ys)**2)

Xs = X.copy(); Xs[:, 1:] = (X[:, 1:] - X[:, 1:].mean(0)) / X[:, 1:].std(0)
for lr in (0.5, 0.1, 0.01, 0.001, 0.0001):
    a = latih(X, lr); b = latih(Xs, lr)
    fa = "MELEDAK" if a is None else f"{a:.5f}"
    fb = "MELEDAK" if b is None else f"{b:.5f}"
    print(f"lr={lr:<8} tanpa dibakukan: {fa:>10}   dibakukan: {fb:>10}")

Versi yang dibakukan mencapai MSE 0,04714 pada tiga learning rate berbeda — ia tidak rewel. Versi yang tidak dibakukan meledak pada ketiganya, dan pada laju yang cukup kecil untuk selamat (0,001) ia berhenti di 0,20354 — lebih dari empat kali lebih buruk.

Ini bukan soal kecepatan saja. Tanpa pembakuan, tidak ada satu pun learning rate yang bekerja baik: yang cukup besar untuk kolom bersatuan kecil akan meledakkan kolom bersatuan besar. Kamu bukan sedang menyetel angka — kamu sedang mencari sesuatu yang tidak ada.

import numpy as np
from scipy import optimize

r = np.array([1.0, 1.6, 1.2])
neg = lambda x: -np.sum(r * np.sqrt(np.maximum(x, 0)))

Verifikasi jawaban solver dengan turunan tangan

Jangan pernah percaya solver tanpa memeriksanya. Metode pengali Lagrange memberi syarat: pada titik optimum, turunan tiap cabang harus sama — kalau tidak, memindahkan satu rupiah dari cabang berturunan kecil ke yang besar akan menaikkan total.

Turunan hasil cabang i terhadap x_i:
      d/dx [ r_i * akar(x_i) ]  =  r_i / (2*akar(x_i))

Syarat optimum: semua sama dengan pengali lambda.

      r_i / (2*akar(x_i)) = lambda
      akar(x_i)           = r_i / (2*lambda)
      x_i                 = r_i^2 / (4*lambda^2)

Jadi x_i SEBANDING dengan r_i KUADRAT.
Dengan kendala jumlah = 100:

      x_i = 100 * r_i^2 / (r_1^2 + r_2^2 + r_3^2)
