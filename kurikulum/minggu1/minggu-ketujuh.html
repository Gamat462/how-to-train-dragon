HARI 43

Confidence interval: jawaban yang jujur

± 50 menit

Akhir hari ini kamu bisa: melaporkan hasil A/B test sebagai rentang (confidence interval), bukan satu angka p-value — kebiasaan yang langsung terlihat oleh pewawancara sebagai tanda analis yang matang.

1

Muat ulang data + uji ingatan

Colab baru. Muat abtest_checkout.csv (Hari 27). Tanpa melihat: tulis kode tingkat konversi tiap grup dan p-value-nya.

Cek jawabanku

Konversi: ab.groupby("grup")["konversi"].mean() → kontrol 11,225%, perlakuan 12,775%. p-value: chi2_contingency(pd.crosstab(ab.grup, ab.konversi), correction=False) → 0,0329.

2

Masalah dengan p-value saja

p-value cuma menjawab ya/tidak: "apakah bedanya nyata?" Tapi atasanmu akan bertanya lanjutan: "seberapa besar bedanya, dan seberapa yakin kita?" p-value tidak menjawab itu. Confidence interval (CI) menjawabnya.

3

Menghitung CI 95%

import numpy as np

p1 = ab[ab.grup=="kontrol"]["konversi"].mean()
p2 = ab[ab.grup=="perlakuan"]["konversi"].mean()
n1 = n2 = 4000

se_ci = np.sqrt(p1*(1-p1)/n1 + p2*(1-p2)/n2)
selisih = p2 - p1
lo, hi = selisih - 1.96*se_ci, selisih + 1.96*se_ci

print(f"selisih = {selisih*100:.2f} poin persen")
print(f"CI 95%  = [{lo*100:.2f}, {hi*100:.2f}] poin persen")
HARUS MUNCUL

selisih = 1.55 poin persen
CI 95% = [0.13, 2.97] poin persen

Baca begini: efek sebenarnya kemungkinan besar ada di antara +0,13 dan +2,97 poin persen. Rentangnya lebar sekali — batas bawahnya nyaris nol. Kita tahu efeknya positif, tapi hampir tidak tahu seberapa positif.

Hubungan CI dan p-value: kalau CI 95% tidak memuat angka nol, maka otomatis p < 0,05. Keduanya bicara hal yang sama — tapi CI memberi jauh lebih banyak informasi (besaran dan ketidakpastian), bukan cuma ya/tidak. Mulai sekarang, selalu laporkan CI di samping p-value.

HARI 44

Effect size: signifikan belum tentu berarti

± 45 menit

Akhir hari ini kamu bisa: menghitung Cohen's d, dan menjelaskan kenapa hasil yang "signifikan secara statistik" bisa saja tidak penting secara bisnis.

1

Masalah dengan sampel besar

Ingat Hari 24 (Central Limit Theorem): makin besar sampel, makin sempit ketidakpastiannya. Konsekuensinya: dengan sampel cukup besar, perbedaan sekecil apa pun — bahkan yang tidak ada artinya secara bisnis — akan lolos jadi "signifikan secara statistik". Effect size mengukur besarnya perbedaan dalam satuan yang tidak bergantung pada ukuran sampel.

2

Cohen's d

sp = np.sqrt(
    ((len(aov_kontrol)-1)*aov_kontrol.var(ddof=1) +
     (len(aov_perlakuan)-1)*aov_perlakuan.var(ddof=1)) /
    (len(aov_kontrol)+len(aov_perlakuan)-2)
)
d = (aov_perlakuan.mean() - aov_kontrol.mean()) / sp
print(f"Cohen's d = {d:.3f}")
HARUS MUNCUL

Cohen's d = -0.131

3

Membaca ukurannya

|d|Ukuran efek
~0,2Kecil
~0,5Sedang
~0,8Besar

d = 0,131 itu sangat kecil — signifikan secara statistik (p=0,043 dari Hari 26-27), tapi nyaris tidak berarti secara praktis. Penurunan Rp 3.216 per pesanan mungkin tidak layak dikhawatirkan sendirian — tapi tetap perlu dicek lewat pendapatan total (RPV), seperti yang kamu lakukan di Hari 27.

Ini kesalahan yang sangat sering dilakukan analis pemula: melihat p<0,05 lalu langsung menyimpulkan "penting". p-value hanya bicara soal kepercayaan bahwa efeknya bukan nol — bukan soal seberapa besar efeknya. Selalu laporkan effect size di samping p-value, terutama untuk sampel besar.
4

Coba sendiri

Effect size untuk proporsi (seperti konversi) dihitung beda (disebut Cohen's h), tapi intuisinya sama. Tanpa menghitung persis, menurutmu: selisih konversi 1,55 poin persen (dari 11,2% ke 12,8%) itu efek besar atau kecil secara relatif?

Buka diskusi

Secara absolut kecil (1,55pp), tapi secara relatif itu kenaikan 13,8% dari baseline — cukup besar untuk bisnis. Ini contoh kenapa "besar" itu tergantung konteks: pp absolut vs persen relatif bisa memberi kesan sangat berbeda. Selalu sebutkan keduanya saat melapor.

Hari 44 selesai

Tambahkan ke catatan: Cohen's d ≈0,2 kecil / 0,5 sedang / 0,8 besar. Signifikan (p kecil) ≠ penting (effect size besar) — sampel besar bisa membuat efek sepele jadi "signifikan".

HARI 45

Peeking: kenapa mengintip hasil setiap hari itu curang

± 55 menit

Akhir hari ini kamu bisa: membuktikan sendiri lewat simulasi kenapa menghentikan tes begitu "menang" adalah kesalahan statistik yang sangat umum — dan sangat merugikan.

1

Kebiasaan yang terlihat masuk akal

Bayangkan kamu menjalankan A/B test, mengecek hasilnya tiap hari, dan berhenti begitu p<0,05 muncul — "kenapa buang waktu kalau sudah menang?" Kedengarannya efisien dan hemat waktu. Sebenarnya ini salah satu kesalahan paling mahal di dunia A/B testing.

2

Buktinya: A/A test — dua grup yang identik

Kita simulasikan dua grup yang benar-benar sama (tidak ada fitur baru, tidak ada efek apa pun), lalu lihat berapa sering pengecekan berulang membuat kita "menang" secara kebetulan:

rng = np.random.default_rng(2024)

def simulasi_peek(jumlah_cek, n_total=4000, p=0.11, percobaan=4000):
    titik = np.linspace(n_total // jumlah_cek, n_total, jumlah_cek).astype(int)
    palsu = 0
    for _ in range(percobaan):
        a = rng.random(n_total) < p      # dua grup, TIDAK ADA efek sungguhan
        b = rng.random(n_total) < p
        for t in titik:
            x1, x2 = a[:t].sum(), b[:t].sum()
            pp = (x1 + x2) / (2*t)
            se = np.sqrt(pp*(1-pp)*2/t)
            if se > 0 and abs((x2-x1)/t/se) > 1.96:
                palsu += 1
                break                     # berhenti begitu "menang"
    return palsu / percobaan

for c in (1, 5, 20):
    print(f"cek {c:2d}x -> {simulasi_peek(c)*100:.1f}% 'menang' padahal tidak ada efek")
HARUS MUNCUL (butuh sekitar 1-2 menit menjalankan)

cek 1x -> 4.8% 'menang' padahal tidak ada efek
cek 5x -> 13.8% 'menang' padahal tidak ada efek
cek 20x -> 25.8% 'menang' padahal tidak ada efek

3

Kenapa ini terjadi

Cek 1x: hasilnya persis 4,8% ≈ 5% — sesuai teori (α=0,05). Tapi begitu kamu cek 20 kali dan berhenti begitu menang, angka false positive-nya meledak ke 25,8% — lebih dari 1 dari 4!

Kalau timmu mengecek dashboard A/B test tiap hari selama 20 hari dan langsung merayakan begitu p<0,05 muncul, satu dari empat "kemenangan" seperti itu murni kebetulan — fitur barunya sama sekali tidak berpengaruh. Ini bukan teori, ini penyebab utama kenapa banyak "kemenangan" A/B test tidak pernah terlihat efeknya di angka bisnis riil setelah diluncurkan.
Obatnya: tentukan ukuran sampel/durasi tes di depan (kamu akan belajar caranya Hari 48), lalu jangan lihat hasilnya sampai tes selesai. Kalau memang perlu memantau progres secara berkala, gunakan metode sequential testing yang dirancang khusus untuk itu — bukan uji-t/chi-square biasa yang diulang-ulang.
4

Coba sendiri

Jalankan simulasi_peek(40) — 40 kali pengecekan. Berapa persen false positive-nya? Apakah kenaikannya dari 20x ke 40x sebesar dari 5x ke 20x?

Buka jawaban

Sekitar 31%. Naik dari 25,8% ke 31% (kenaikan 5pp), lebih kecil dari kenaikan 5x→20x (13,8%→25,8%, kenaikan 12pp). Makin sering mengintip makin buruk, tapi laju kenaikannya melambat — karena pengecekan yang berdekatan waktu hasilnya cenderung mirip (tidak sepenuhnya independen).

Hari 45 selesai

Tambahkan ke catatan: mengintip hasil A/B test berulang kali dan berhenti saat "menang" membuat tingkat false positive melonjak jauh di atas 5% — buktinya dari simulasi A/A test sendiri, bukan cuma teori.

HARI 46

Multiple comparisons: menguji banyak metrik sekaligus

± 45 menit

Akhir hari ini kamu bisa: menjelaskan kenapa menguji banyak metrik memperbesar peluang menemukan "kemenangan" palsu, dan menerapkan koreksi Bonferroni.

1

Jebakan kedua: menguji terlalu banyak hal

Tiap uji statistik dengan α=0,05 punya peluang 5% menghasilkan false positive walau tidak ada efek sungguhan (ingat: itu definisi p-value dari Hari 26). Kalau kamu menguji banyak metrik sekaligus (konversi, AOV, RPV, retensi, waktu di halaman, ...), peluang setidaknya satu yang "menang" secara kebetulan naik cepat.

2

Hitung peluangnya

for m in (1, 5, 10, 20):
    peluang = (1 - 0.95**m) * 100
    print(f"{m:2d} metrik -> peluang minimal 1 false positive: {peluang:.1f}%")
HARUS MUNCUL

1 metrik -> peluang minimal 1 false positive: 5.0%
5 metrik -> peluang minimal 1 false positive: 22.6%
10 metrik -> peluang minimal 1 false positive: 40.1%
20 metrik -> peluang minimal 1 false positive: 64.2%

Dengan 20 metrik yang diuji, ada peluang 64% setidaknya satu akan "signifikan" murni karena kebetulan — bukan karena ada efek sungguhan. Rumusnya 1 - 0.95^m: peluang tidak ada satu pun false positive dari m uji independen adalah 0,95 pangkat m.

3

Obatnya: satu metrik utama + koreksi Bonferroni

Cara terbaik: tentukan satu metrik utama sebelum tes dimulai (ingat Hari 27 — RPV). Metrik lain jadi pendukung, bukan penentu keputusan.

Kalau memang harus menguji banyak metrik sekaligus sebagai metrik utama, perketat ambang batasnya — koreksi Bonferroni: bagi 0,05 dengan jumlah uji.

jumlah_metrik = 8
ambang_bonferroni = 0.05 / jumlah_metrik
print(ambang_bonferroni)
HASIL

0.00625 — dengan 8 metrik, p harus lebih kecil dari 0,00625 (bukan 0,05) untuk dianggap signifikan.

4

Jebakan tersembunyi: memotong data sampai ketemu kemenangan

Tes gagal secara keseluruhan, lalu seseorang bilang: "tapi coba lihat pengguna Android di Jakarta usia 25-34 — di situ naik 40%!" Ini adalah multiple comparisons dalam bentuk tersembunyi — memecah data ke banyak segmen sampai ketemu satu yang "menang" itu sama saja dengan menguji banyak metrik, hampir selalu kebetulan.

Analisis per segmen boleh dilakukan — tapi hasilnya adalah hipotesis untuk tes berikutnya, bukan kesimpulan final. Kalau kamu menemukan pola menarik di satu segmen setelah tes selesai, jalankan tes baru yang khusus menguji segmen itu, dengan hipotesis yang ditentukan di awal — jangan langsung ambil kesimpulan dari pola yang "ditemukan" setelah melihat data.
5

Coba sendiri

Timmu menguji 8 metrik dan salah satunya keluar dengan p=0,03. Apakah kamu percaya itu efek nyata?

Buka jawaban

Jangan langsung percaya. Dengan 8 metrik, peluang minimal satu false positive = 1-0,95⁸ = 33,7%. Ambang Bonferroni untuk 8 metrik = 0,05/8 = 0,00625, dan p=0,03 tidak lolos ambang itu. Perlakukan sebagai hipotesis, lalu uji ulang khusus metrik itu di tes terpisah.

Hari 46 selesai

Tambahkan ke catatan: peluang false positive naik dengan jumlah metrik yang diuji (1-0.95^m). Koreksi Bonferroni: ambang = 0,05/jumlah uji. Tentukan satu metrik utama sebelum tes dimulai.

HARI 48

Merancang tes dari awal: berapa sampel yang dibutuhkan?

± 55 menit

Akhir hari ini kamu bisa: menghitung ukuran sampel sebelum tes dimulai, dan mengevaluasi apakah tes yang sudah selesai (Hari 27) sebenarnya cukup kuat untuk dipercaya.

1

Empat masukan yang dibutuhkan

Sebelum tes dimulai, jawab dulu:

  • Baseline — konversi sekarang (11%)
  • MDE (minimum detectable effect) — kenaikan terkecil yang layak diperjuangkan bisnis. Ini keputusan bisnis, bukan statistik.
  • α — biasanya 0,05 (ambang batas false positive yang kamu terima)
  • Power — biasanya 0,80 (peluang mendeteksi efek kalau memang ada)
2

Menghitung ukuran sampel

from scipy import stats

def n_per_grup(p1, mde_relatif, alpha=0.05, power=0.80):
    p2 = p1 * (1 + mde_relatif)
    z_a = stats.norm.ppf(1 - alpha/2)
    z_b = stats.norm.ppf(power)
    pbar = (p1 + p2) / 2
    n = (z_a*np.sqrt(2*pbar*(1-pbar)) +
         z_b*np.sqrt(p1*(1-p1) + p2*(1-p2)))**2 / (p2-p1)**2
    return int(np.ceil(n))

for mde in (0.05, 0.10, 0.15, 0.20):
    n = n_per_grup(0.11, mde)
    print(f"MDE {int(mde*100):2d}% relatif -> {n:7,} per grup ({2*n:,} total)")
HARUS MUNCUL

MDE 5% relatif -> 51,912 per grup (103,824 total)
MDE 10% relatif -> 13,253 per grup ( 26,506 total)
MDE 15% relatif -> 6,011 per grup ( 12,022 total)
MDE 20% relatif -> 3,449 per grup ( 6,898 total)

Perhatikan betapa mahalnya efek kecil: mendeteksi kenaikan 5% butuh 15 kali lebih banyak pengunjung dibanding kenaikan 20%. Inilah kenapa perusahaan dengan trafik kecil sebaiknya hanya menguji perubahan besar — menguji perubahan warna tombol butuh trafik yang mereka tidak punya.
3

Kabar buruk: hitung ulang power tes Hari 27

Sekarang tes kebalikannya — tes Hari 27 sudah selesai dengan n=4.000 per grup. Berapa power tes itu sebenarnya?

p1, p2, n = 0.11225, 0.12775, 4000
z_a = stats.norm.ppf(0.975)
se_null = np.sqrt(2*((p1+p2)/2)*(1-(p1+p2)/2)/n)
se_alt  = np.sqrt(p1*(1-p1)/n + p2*(1-p2)/n)
power = (1 - stats.norm.cdf((z_a*se_null - (p2-p1))/se_alt)
           + stats.norm.cdf((-z_a*se_null - (p2-p1))/se_alt))
print(f"power = {power*100:.1f}%")
HARUS MUNCUL

power = 56.9%

Hanya 57%. Padahal efeknya benar-benar ada di data kita. Artinya kalau eksperimen ini diulang 100 kali dengan trafik segini, 43 kali di antaranya akan gagal menemukan efek yang nyata — kita di Hari 27 sebenarnya beruntung. Untuk mendeteksi kenaikan 13,8% dengan power 80% yang layak, seharusnya dipakai sekitar 7.000 pengunjung per grup, bukan 4.000.
4

Menyusun ulang kesimpulan Hari 27 dengan lebih jujur

Sekarang uji RPV (Hari 27 langkah 5) secara formal — bukan cuma bandingkan mean-nya:

t, p = stats.ttest_ind(
    ab[ab.grup=="perlakuan"]["nilai_pesanan"],
    ab[ab.grup=="kontrol"]["nilai_pesanan"],
    equal_var=False
)
print(f"t = {t:.4f}   p = {p:.4f}")
HARUS MUNCUL

t = 1.4149 p = 0.1571

Konversi+13,8%p=0,033 · CI [+0,13, +2,97]pp

Pendapatan/pengunjung+9,4%p=0,157 · TIDAK signifikan
Ini mengubah rekomendasi Hari 27. Waktu itu kamu menyimpulkan "RPV naik, jadi luncurkan" — cukup masuk akal untuk analis pemula. Tapi sekarang kamu tahu: RPV naik 9,4% secara angka, tapi tidak signifikan secara statistik (p=0,157) — bisa saja itu kebetulan. Ditambah power tes cuma 57%. Rekomendasi yang lebih tepat: lanjutkan tes 2 minggu lagi dengan trafik lebih besar, bukan langsung meluncurkan berdasarkan bukti yang masih lemah.
5

Coba sendiri

Buka jawaban

n_per_grup(0.11, 0.138) → sekitar 7.000 per grup — mengonfirmasi angka yang disebut di langkah 3. Tes Hari 27 memakai 4.000, jauh di bawah kebutuhan sebenarnya untuk power 80%.

## Proyek 6: Laporan Keputusan A/B Test

Analisis lengkap tiga metrik (konversi, AOV, RPV) dengan confidence
interval dan effect size, perhitungan power (57% - kurang dari
ambang layak 80%), dan simulasi pembuktian kenapa "mengintip" hasil
berulang kali membesar-besarkan tingkat false positive.

**Rekomendasi:** lanjutkan tes, bukan langsung luncurkan - power
belum cukup dan metrik pendapatan belum signifikan.

**Berkas:** [06-abtest-laporan-keputusan.ipynb](06-abtest-laporan-keputusan.ipynb)
Latih ini dengan suara keras sebelum wawancara: "Kenapa tidak boleh menghentikan tes begitu hasilnya signifikan?" — jawab dengan angka simulasi Hari 45 (5%→26% false positive). "Metrik utama naik tapi metrik lain turun, apa yang kamu lakukan?" — jawab dengan RPV sebagai metrik gabungan. Pewawancara sangat menghargai jawaban yang pakai angka konkret, bukan cuma teori.

Tujuh minggu selesai — statistik terapan tingkat menengah dikuasai
