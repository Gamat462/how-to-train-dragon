HARI 85

Data churn, dan model pertama: regresi logistik

± 55 menit

Akhir hari ini kamu bisa: melatih model prediksi churn, dan membaca isinya dalam kalimat yang dimengerti orang non-teknis.

1

Data: perilaku 30 hari pertama

Colab baru. Untuk tiap pelanggan, kita punya perilakunya di 30 hari pertama, dan label apakah dia akhirnya berhenti (churn). Tugas model: menebak label itu untuk pelanggan baru yang belum kita tahu nasibnya.

import numpy as np
import pandas as pd

rng = np.random.default_rng(21)
N = 5000

trx_30d       = rng.poisson(3.2, N)
hari_terakhir = rng.integers(1, 60, N)
nilai_avg     = rng.normal(78000, 25000, N).clip(15000)
pakai_promo   = rng.random(N) < 0.38
kanal         = rng.choice(["organik", "iklan", "referral"], N, p=[0.45, 0.40, 0.15])
produk_beda   = rng.integers(1, 6, N)

logit = (-0.55 - 0.42*trx_30d + 0.055*hari_terakhir - 0.30*produk_beda
         + 0.55*(kanal == "iklan") - 0.45*(kanal == "referral")
         + 0.25*pakai_promo - 0.0000035*(nilai_avg - 78000))
churn = (rng.random(N) < 1/(1 + np.exp(-logit))).astype(int)

df = pd.DataFrame({
    "trx_30d": trx_30d, "hari_sejak_transaksi_terakhir": hari_terakhir,
    "nilai_rata2": nilai_avg.round(-2), "pakai_promo": pakai_promo.astype(int),
    "kanal": kanal, "jumlah_produk_beda": produk_beda, "churn": churn,
})

print(df.shape, "| churn rate:", f"{df.churn.mean()*100:.1f}%")
print(df.groupby("kanal").churn.mean().round(3))
HARUS MUNCUL

(5000, 7) | churn rate: 33.2%
iklan 0.385 · organik 0.313 · referral 0.246

Sudah ada satu temuan sebelum model apa pun dilatih: pelanggan dari referral paling jarang pergi (24,6%), dari iklan paling sering (38,5%). Digabung dengan pelajaran LTV Minggu 12, artinya CAC untuk kanal iklan seharusnya dipatok lebih rendah daripada referral — pelanggannya bernilai lebih kecil. Selalu jalankan groupby sederhana dulu sebelum melatih model — sering kali temuan terpentingnya sudah muncul di situ.
2

Memisahkan data latih dan uji

from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.linear_model import LogisticRegression

X = pd.get_dummies(df.drop(columns="churn"), columns=["kanal"], drop_first=True)
y = df.churn

X_latih, X_uji, y_latih, y_uji = train_test_split(
    X, y, test_size=0.25, random_state=42, stratify=y)
print(X_latih.shape, X_uji.shape)
HARUS MUNCUL

(3750, 7) (1250, 7)

stratify=y memastikan proporsi churn sama di kedua bagian — tanpa itu, kebetulan pembagian bisa membuat data uji punya komposisi jauh berbeda.

Data uji itu suci. Kamu hanya boleh menyentuhnya sekali, di akhir, untuk melaporkan hasil. Kalau kamu mencoba sepuluh model dan memilih yang skornya paling bagus di data uji, kamu sebenarnya sedang menyesuaikan diri ke data uji itu — angka yang kamu laporkan akan lebih optimistis daripada kenyataan. Untuk memilih antar model, pakai cross-validation di data latih (Hari 89).
3

Melatih regresi logistik, dan membaca odds ratio

lr = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
lr.fit(X_latih, y_latih)

prob = lr.predict_proba(X_uji)[:, 1]      # peluang churn, 0 sampai 1
pred = lr.predict(X_uji)                  # keputusan ya/tidak (ambang 0,5)

koef = pd.Series(lr[-1].coef_[0], index=X.columns).sort_values()
print(np.exp(koef).round(3))              # odds ratio
HARUS MUNCUL

trx_30d 0.450 · jumlah_produk_beda 0.628 · kanal_referral 0.748 · kanal_organik 0.808 · nilai_rata2 0.894 · pakai_promo 1.142 · hari_sejak_transaksi_terakhir 2.548

Cara membaca odds ratio: di atas 1 menaikkan peluang churn, di bawah 1 menurunkannya (per satu simpangan baku, karena fiturnya distandarkan). Tiap satu simpangan baku tambahan pada jarak dari transaksi terakhir, peluang churn jadi 2,5× lipat. Tiap satu simpangan baku tambahan jumlah transaksi memangkas peluangnya jadi 0,45×.

Inilah kenapa regresi logistik sering menang di dunia nyata: kamu bisa duduk bersama pemilik kedai dan bilang "pelanggan yang belum belanja lama jauh lebih mungkin hilang, dan pelanggan yang mencoba banyak jenis produk jauh lebih mungkin bertahan". Kalimat itu langsung berubah jadi tindakan.

Model kedua: random forest, dan jebakan feature importance

± 55 menit

Akhir hari ini kamu bisa: melatih random forest, dan mengenali kenapa feature_importances_ bawaannya bisa menyesatkan.

1

Random forest: kumpulan pohon yang memberi suara

from sklearn.ensemble import RandomForestClassifier

rf = RandomForestClassifier(n_estimators=300, min_samples_leaf=5, random_state=42)
rf.fit(X_latih, y_latih)

penting = pd.Series(rf.feature_importances_, index=X.columns)
print(penting.sort_values(ascending=False).round(3))
HARUS MUNCUL

hari_sejak_transaksi_terakhir 0.401 · trx_30d 0.213 · nilai_rata2 0.202 · jumlah_produk_beda 0.112 · pakai_promo 0.027 · kanal_organik 0.025 · kanal_referral 0.019

min_samples_leaf=5 mencegah pohon menghafal data latih. Tanpa pembatas ini, random forest mendapat akurasi hampir sempurna di data latih dan jelek di data uji — itulah overfitting.

2

Jebakan feature_importances_

Ukuran ini cenderung memihak fitur dengan banyak nilai berbeda. Perhatikan nilai_rata2 mendapat 0,202 — terlihat penting — padahal di regresi logistik (Hari 85) pengaruhnya paling lemah (odds ratio 0,894, hampir 1). Yang benar adalah regresi logistik: kita tahu dari cara data dibuat (koefisien -0.0000035, nyaris nol) bahwa pengaruh nilai_rata2 memang sangat kecil.

Untuk pengukuran yang lebih jujur:

from sklearn.inspection import permutation_importance
hasil = permutation_importance(rf, X_uji, y_uji, n_repeats=10, random_state=42)
pd.Series(hasil.importances_mean, index=X.columns).sort_values(ascending=False)

Cara ini mengukur seberapa turun kinerja model saat satu kolom diacak (diukur di data uji, jauh lebih jujur) — nilai_rata2 akan turun peringkatnya secara mencolok dibanding feature_importances_ bawaan.

3

HARI 88

Dari model ke rupiah: ambang keputusan dan nilai bisnis

± 65 menit

Akhir hari ini kamu bisa: membuktikan model dengan AUC bagus bisa tetap membuat kampanye rugi — dan menghitung ambang yang benar-benar menguntungkan.

1

Ambang 0,5 itu pilihan sembarang

Model menghasilkan peluang, bukan keputusan. Angka 0,5 hanyalah bawaan pustaka. Model yang sama, tanpa dilatih ulang, bisa menandai 576 orang (ambang 0,3) atau 110 orang (ambang 0,7) — mana yang benar? Jawabannya ada di ekonomi kampanyenya, bukan di dalam model.

2

Menghitung untung-rugi tiap ambang

Andaikan kedai mengirim voucher Rp 25.000 ke tiap pelanggan yang ditandai, berhasil menahan 30% yang memang akan pergi. Nilai satu pelanggan yang selamat = margin LTV (Minggu 12): Rp 109.000.

from sklearn.metrics import confusion_matrix

BIAYA, EFEKTIF, NILAI = 25_000, 0.30, 109_000

for t in (0.3, 0.4, 0.5, 0.6, 0.7, 0.8):
    pred = (prob >= t).astype(int)
    tn, fp, fn, tp = confusion_matrix(y_uji, pred).ravel()
    biaya   = pred.sum() * BIAYA
    manfaat = tp * EFEKTIF * NILAI
    print(f"ambang {t}: ditandai {pred.sum():4d}  biaya {biaya:>11,}"
          f"  manfaat {manfaat:>11,.0f}  laba {manfaat-biaya:>12,.0f}")
HARUS MUNCUL

ambang 0.3: laba -4,164,900
ambang 0.5: laba -886,900
ambang 0.7: laba -3,200
ambang 0.8: laba -109,400

Rugi di semua ambang. Modelnya bagus — AUC 0,797, jauh di atas tebakan acak — tapi kampanyenya tetap membakar uang. Kalau kamu berhenti di "AUC saya 0,80" dan menyerahkannya ke tim pemasaran, kamu baru saja merekomendasikan sesuatu yang merugikan perusahaan.
3

Rumus presisi impas

presisi impas = biaya ÷ (efektivitas × nilai)
Untuk kasus ini: 25.000 ÷ (0,30 × 109.000) = 0,765. Kampanye baru menguntungkan kalau presisi model melebihi 76,5%. Presisi tertinggi yang bisa dicapai model kita adalah 76,4% (ambang 0,7 dari Minggu ini) — persis di bawah garis. Rumus satu baris ini memberi tahu jawabannya sebelum kamu melatih model apa pun.
4

Yang harus diubah: intervensinya, bukan modelnya

Karena presisi impas terlalu tinggi, jalan keluarnya bukan model lebih canggih — jalan keluarnya membuat intervensi lebih murah. Ganti voucher Rp 25.000 dengan pesan pengingat + voucher kecil Rp 10.000, efektivitas sama:

AmbangLaba bersihROI
0,3+4.475.10078%
0,5+3.628.100121%
0,7+1.646.800150%

Sekarang semuanya untung, dan ambang terbaik berpindah dari 0,7 ke 0,3. Ketika intervensinya murah, kamu justru ingin menebar jaring selebar mungkin.

Laba bersih vs ROI: ambang 0,7 punya ROI tertinggi (150%) tapi laba terkecil (Rp1,6jt). Ambang 0,3 ROI terendah tapi laba terbesar (Rp4,5jt). Kalau anggaran ada, kejar laba bersih; kalau anggaran dijatah, kejar ROI. Mengirim ke semua 1.250 pelanggan tanpa model = laba Rp1.070.500 — nilai tambah model dengan ambang 0,3 sekitar Rp3,4 juta, dan angka itulah yang harus ada di kalimat pertama laporanmu, bukan AUC.

HARI 89

Segmentasi RFM, dan kebocoran data

± 55 menit

Akhir hari ini kamu bisa: membuat segmen pelanggan dengan nama yang langsung menyarankan tindakan, dan mengenali kesalahan yang membuat model palsu terlihat sempurna.

1

RFM: cara paling praktis mengelompokkan pelanggan

# Recency, Frequency, Monetary
rfm = df.assign(
    R = pd.qcut(df.hari_sejak_transaksi_terakhir, 4, labels=[4,3,2,1]).astype(int),
    F = pd.qcut(df.trx_30d.rank(method="first"),  4, labels=[1,2,3,4]).astype(int),
    M = pd.qcut(df.nilai_rata2,                   4, labels=[1,2,3,4]).astype(int),
)
rfm["skor"] = rfm.R + rfm.F + rfm.M

def label(baris):
    if baris.skor >= 10:                    return "Juara"
    if baris.R >= 3 and baris.F <= 2:       return "Baru, berpotensi"
    if baris.R <= 2 and baris.F >= 3:       return "Berisiko hilang"
    if baris.skor <= 5:                     return "Hampir hilang"
    return "Perlu perhatian"

rfm["segmen"] = rfm.apply(label, axis=1)
rfm.groupby("segmen").agg(jumlah=("skor","size"), churn=("churn","mean")).round(3)

RFM sering mengalahkan k-means untuk keperluan bisnis, karena segmennya punya nama yang dimengerti orang dan langsung menyarankan tindakan. "Berisiko hilang" adalah instruksi; "Cluster 3" bukan.

2

Kebocoran data: kesalahan yang paling memalukan

Kebocoran terjadi saat model diam-diam melihat informasi yang di dunia nyata belum tersedia saat prediksi dibuat. Gejalanya khas: akurasi luar biasa tinggi, orang di sekitarmu terkesan — lalu model gagal total saat dipakai sungguhan.

Bentuk kebocoranContohCara menghindari
Fitur dari masa depanPakai "transaksi bulan ke-3" untuk prediksi churn bulan ke-3Semua fitur harus dari sebelum titik prediksi
Akibat, bukan sebabPakai "sudah menutup akun" sebagai fiturTanya: apakah kolom ini hasil dari yang diprediksi?
Standarisasi sebelum splitStandardScaler pada seluruh data sebelum train_test_splitBungkus dengan Pipeline (seperti Hari 85)
Aturan praktis: kalau akurasimu di atas 95% pada masalah bisnis yang sulit, jangan senang dulu — curigai kebocoran. Masalah nyata jarang semudah itu. Menemukan kebocoran di pekerjaanmu sendiri dan melaporkannya adalah tanda analis yang bisa dipercaya.
3

Validasi silang untuk memilih model

from sklearn.model_selection import cross_val_score

for nama, model in [("logistik", lr), ("random forest", rf)]:
    skor = cross_val_score(model, X_latih, y_latih, cv=5, scoring="roc_auc")
    print(f"{nama:15s} AUC {skor.mean():.3f} ± {skor.std():.3f}")

Ini membagi data latih jadi 5 bagian dan menguji 5 kali — kamu dapat rata-rata dan sebaran. Simpangan besar = hasil tidak stabil, jangan dipercaya terlalu jauh. Pakai ini untuk memilih model; simpan data uji untuk laporan akhir saja.

## Proyek 11: Model Prediksi Churn + Memo Bisnis

Regresi logistik vs random forest untuk memprediksi churn pelanggan
(dipilih lewat cross-validation), dengan analisis nilai bisnis yang
menunjukkan model berkualitas baik (AUC 0,80) tetap bisa membuat
kampanye rugi tanpa ambang keputusan yang tepat.

**Nilai tambah model:** ~Rp 3,4 juta laba tambahan dibanding tanpa
model, pada ambang optimal.

**Berkas:** [11-model-churn.ipynb](11-model-churn.ipynb), [11-memo-churn.md](11-memo-churn.md)
Latih dengan suara keras sebelum wawancara: "Model kami akurasinya 98%, apa reaksi pertamamu?" → "Saya akan curiga ada kebocoran, dan hal pertama yang saya periksa adalah apakah ada fitur yang sebenarnya merupakan akibat dari hal yang kami prediksi." Jawaban ini hampir selalu benar dan menunjukkan kematangan.
